# AGENTS.md

## Project overview

Single Django project (`flowpro`) with one app (`trades`). A mobile-first plumbing/trades website with booking enquiry form, testimonial submission via signed links, and a BusinessProfile model that controls all site copy — no template edits needed for content changes.

- **Project package:** `flowpro/` (settings, root URLconf, WSGI)
- **App package:** `trades/` (models, views, forms, admin, templates, static, templatetags)
- **Settings entrypoint:** `DJANGO_SETTINGS_MODULE=flowpro.settings` (hardcoded in `manage.py`, `wsgi.py`, and deploy script)
- **All config** comes from `.env` via `python-decouple` (`decouple.config()`)

## Commands

```bash
# Run tests (needs PostgreSQL by default; use SQLite if PG unavailable)
python manage.py test

# Run tests without PostgreSQL
DATABASE_URL=sqlite:///:memory: python manage.py test

# Pre-deploy checks (run in this order)
python manage.py check
python manage.py makemigrations --check --dry-run        # verify no missing migrations
python manage.py test

# Collect static files into staticfiles/ (required before deploy; .gitignored)
python manage.py collectstatic --noinput

# Run dev server (serves media in DEBUG mode)
python manage.py runserver

# Local/LAN deploy (self-contained Nginx + Gunicorn on ports 8021/9021, HTTP-only)
bash deploy/home/start.sh --foreground

# Production deploy (pip install + preflight checks + systemd restart)
bash deploy/start.sh
```

## Architecture notes

- **`_site_context()`** in `trades/views.py:23` is the single context builder used by every page view. It fetches the active `BusinessProfile` with `prefetch_related` on trust_indicators, service_offerings, testimonials, and legal_pages. Any new page context should pass through this function.
- **BusinessProfile-driven content:** Every piece of customer-facing copy (hero headline, service titles, phone number, meta description, etc.) lives on the active `BusinessProfile` model. No hardcoded strings in templates. When cloning for a new client, only Admin edits are needed.
- **Booking flow:** form saves the `BookingEnquiry` first, then attempts to send email to `ADMIN_NOTIFICATION_EMAIL`. Email failure does NOT roll back the booking — the enquiry is persisted and the failure is logged.
- **Testimonial links:** signed tokens (`django.core.signing`) tied to a `BookingEnquiry` PK, 180-day expiry. Generated from `BookingEnquiryAdmin.testimonial_request_link()` and rendered in the list view. URL pattern: `/put/testimonial/<token>/`. Submitted testimonials are saved with `is_active=False` — must be approved in Admin before appearing on the public reviews page.
- **`versioned_static`** template tag (`trades/templatetags/static_version.py`) busts caches using file mtime. Use `{% versioned_static "trades/css/landing.css" %}` instead of `{% static %}` for app static assets. Tests assert this.
- **UK-only validation:** `BookingEnquiryForm` enforces UK phone number regex and UK postcode format. Email is optional. Phone numbers are normalised to `+44` format on save.
- **WhatsApp:** `BusinessProfile.whatsapp_url` is a computed property (not a DB field). The booking page and mobile nav use it — when a WhatsApp number is set, the mobile bottom nav switches from "Call" to "WhatsApp".
- **Rate limiting:** `trades/decorators.py` provides a `@rate_limit` decorator backed by Django's database cache. Configured via `BOOKING_RATE_LIMIT` env var (e.g. `5/m` for 5 POSTs per minute per IP). Leave blank to disable.
- **Cache:** Uses `DatabaseCache` (table `django_cache`). The deploy script runs `createcachetable` at startup. For tests with SQLite `:memory:`, the cache table is created automatically.
- **Sitemap & robots.txt:** `/sitemap.xml` (Django `django.contrib.sitemaps`) and `/robots.txt` are served at the root. Sitemap includes static pages, service detail pages, and legal pages.
- **Logging:** Rotating file logs at `logs/django.log` (5 MB, 3 backups) plus console output. Log level controlled by `LOG_LEVEL` env var (default `INFO`).
- **No linter, formatter, or typecheck config** exists in this repo. No CI/CD workflows.

## Gotchas

- **Static files are in `.gitignore`.** After cloning or switching branches, `collectstatic` is required before the site serves CSS/JS correctly outside of `DEBUG=True`.
- **The `.home_nginx/nginx.conf` contains hardcoded absolute paths** (to `staticfiles/` and `media/`). This file is regenerated by `deploy/home/start.sh` at startup, so it's safe to ignore, but be aware if you're reading it to debug.
- **Tests rely on default `BusinessProfile` content** (e.g. `assertContains(response, "Quality Workmanship")`). If the initial migration's default values change, these tests will break.
- **`makemigrations --check --dry-run`** is the canonical way to verify no missing migrations (used by the deploy script, not `makemigrations --check` alone).
- **`EmailBackend` is configured indirectly** through `EMAIL_PROVIDER` (console/sender_net/google_workspace/google_workspace_relay/custom_smtp) in settings, not by setting `EMAIL_BACKEND` directly unless using `custom_smtp`.
- **Home deploy script** (`deploy/home/start.sh`) auto-detects free ports starting from 8021/9021, runs preflight checks, and generates a fresh nginx.conf before starting. For production, use `deploy/start.sh` which instead restarts the systemd Gunicorn service.
- **`staticfiles/` and `media/`** are served by Nginx in production (not Django), but served by Django's `static()` helper only in `DEBUG=True` mode.
